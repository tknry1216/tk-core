## 1. 最新バージョンの主要な新機能・変更点

### Go 1.24 (2025年2月リリース)

| カテゴリ | 内容 |
|---------|------|
| **ジェネリック型エイリアス** | 型エイリアスがジェネリクスのパラメータ化に完全対応。定義型と同様にパラメータ付き型エイリアスを使用可能に |
| **ツールディレクティブ** | `go.mod` に `tool` ディレクティブが追加され、実行可能な依存関係を直接管理可能に。従来の `tools.go` ファイルのワークアラウンドが不要に |
| **Swiss Tables** | 組み込み `map` の内部実装を Swiss Tables ベースに刷新。CPU オーバーヘッドが平均 2〜3% 削減 |
| **ポスト量子暗号** | ML-KEM-768 / ML-KEM-1024 (旧 Kyber) を公式実装。NIST 承認の FIPS 203 準拠ポスト量子鍵交換メカニズム |
| **FIPS 140-3 準拠** | ネイティブの FIPS 準拠暗号モジュールを導入。`GOFIPS140` 環境変数で有効化可能。BoringSSL 等のサードパーティ不要に |
| **ベンチマーク改善** | `testing.B.Loop` 関数の追加によりベンチマーク記述が簡素化 |
| **弱参照ポインタ** | `weak` パッケージの導入により、GC に影響されない弱参照が利用可能に |

### Go 1.25 (2025年8月リリース)

| カテゴリ | 内容 |
|---------|------|
| **testing/synctest** | 並行コードのテスト支援パッケージが正式リリース。仮想化された時間でのテストが可能になり、ネットワークサービス等の非同期テストが高速化・安定化 |
| **encoding/json/v2** | 実験的な新 JSON 実装。`GOEXPERIMENT=jsonv2` で有効化。`encoding/json` の大規模リビジョン |
| **Green Tea GC (実験)** | 新ガベージコレクタを実験的に導入。小オブジェクトのマーキング・スキャン性能を局所性とCPUスケーラビリティの改善により向上。GCオーバーヘッド 10〜40% 削減が見込まれる |
| **DWARF 5** | コンパイラ・リンカのデバッグ情報形式を DWARF 5 に更新。デバッグ情報のサイズ削減とリンク時間の短縮 |
| **Linux cgroup 対応** | ランタイムが cgroup の CPU 帯域制限を考慮するように改善 |
| **ASan リーク検出** | `go build -asan` がプログラム終了時のメモリリーク検出をデフォルトで有効化 |

### Go 1.26 (2026年2月リリース)

| カテゴリ | 内容 |
|---------|------|
| **Green Tea GC (デフォルト化)** | Go 1.25 で実験的だった Green Tea GC がデフォルトで有効化。GC オーバーヘッド 10〜40% 削減、P99 レイテンシ約 18% 改善の実績報告あり |
| **`new` 関数の拡張** | `new` の引数に式を渡して初期値を指定可能に (`new(int, 42)` のような記法) |
| **cgo オーバーヘッド 30% 削減** | cgo の基本オーバーヘッドが約 30% 削減 |
| **SIMD サポート (実験)** | `simd/archsimd` パッケージによるアーキテクチャ固有の SIMD 操作。`GOEXPERIMENT=simd` で有効化 |
| **runtime/secret (実験)** | 暗号処理で使用される一時データの安全な消去機能 |
| **新パッケージ** | `crypto/hpke`, `crypto/mlkem/mlkemtest`, `testing/cryptotest` の 3 パッケージを追加 |

## 3. パフォーマンス改善・ランタイムの進化

### Green Tea GC の進化

Go のガベージコレクタは 2025〜2026 年で大きな進化を遂げた。

- **設計思想**: 個別オブジェクトのポインタ追跡ではなく、8 KiB メモリページ単位でスキャン。連続メモリアクセスにより CPU プリフェッチが効果的に機能
- **Go 1.25**: 実験的導入 (`GOEXPERIMENT=greenteagc`)
- **Go 1.26**: デフォルト有効化
- **ベンチマーク結果**:
  - GC オーバーヘッド: 10〜40% 削減
  - P99 レイテンシ: 約 18% 改善 (本番 REST API ゲートウェイ、約 80 万 req/s)
  - RSS メモリ: 8〜15% 増加 (トレードオフ)
  - AMD Zen 4 / Intel Ice Lake 以降ではベクトル命令活用で追加 ~10% 改善

### その他のランタイム改善

| バージョン | 改善内容 |
|-----------|---------|
| Go 1.24 | Swiss Tables map 実装、小オブジェクトのメモリ割り当て効率化、新しいランタイム内部 mutex |
| Go 1.25 | DWARF 5 によるバイナリサイズ縮小・リンク高速化、cgroup CPU 帯域制限対応 |
| Go 1.26 | cgo オーバーヘッド 30% 削減、SIMD 操作サポート (実験) |

## 4. コミュニティの動向

### 人気度・採用率

| 指標 | データ |
|------|--------|
| **TIOBE Index** | 2025年4月: 7位 (Go 史上最高)。2026年1月: 16位に下落 (安定性ゆえの「退屈さ」が影響) |
| **Stack Overflow 調査** | 全開発者の 13.5% が Go を選好、プロ開発者では 14.4% |
| **開発者数** | 世界で約 580 万人が Go を使用。JetBrains 調査では過去1年で 410 万人の専門家が利用 |
| **プライマリ言語** | 220 万人が Go を主要言語として使用 (5年前の 2 倍) |
| **成長率** | 2024年に Python・TypeScript に次ぐ 3番目の成長率 |
| **採用予定** | ソフトウェア開発者の 11% が今後 12 ヶ月以内に Go の採用を予定 |

### 2025年 Go 開発者調査

2025年9月に実施された公式 Go Developer Survey には 5,379 名の Go 開発者が回答。コミュニティの強いエンゲージメントと投資が継続していることが示された。

### 給与動向

マイクロサービスや IaC アーキテクチャへの移行に伴い、Go エンジニアの需要が供給を上回り、Go 開発者は業界内で最も高い給与水準のグループに位置している。

## 5. AI/ML関連の動向

### 主要な Go 製 AI/ML ツール

| プロジェクト | 概要 |
|------------|------|
| **Ollama** | Go 製のローカル LLM 実行ツール。llama.cpp バックエンドで消費者向けハードウェア上での LLM 実行を実現。AI インフラの Go 代表格 |
| **LangChainGo** | LangChain の Go 実装。チェーン、エージェント、ツール、エンベディングなどのコンポーザブルコンポーネント。OpenAI, Anthropic, Google AI, AWS Bedrock, Ollama 等多数のプロバイダーに対応 |
| **GoAI** | 22 以上の LLM プロバイダーに対応する Go AI SDK。最小限の依存関係 (2 依存のみ) |
| **KubeAI** | Kubernetes 上の AI 推論ワークロード管理。LLM のコンテナ化デプロイ、スケーリング、リソース割り当て |
| **GoLearn** | Go の機械学習ライブラリ |
| **Gorgonia** | Go のニューラルネットワーク / 機械学習フレームワーク |

### AI/ML における Go の位置づけ

- Go は AI/ML の「推論インフラ層」で強みを発揮。モデル学習は Python が主流だが、推論サービング・API ゲートウェイ・オーケストレーションでは Go が選択されるケースが増加
- Ollama の成功により、Go が LLM インフラの主要言語の一つとして認知
- SRE / DevOps エンジニアが LangChainGo を使って運用自動化エージェントを構築するユースケースが増加

## 7. クラウドネイティブ/マイクロサービス領域

### Go が支えるクラウドネイティブインフラ

Go はクラウドネイティブエコシステムの基盤言語としての地位を確立している。

| プロジェクト | 役割 |
|------------|------|
| **Kubernetes** | コンテナオーケストレーション (Go 製) |
| **Docker** | コンテナランタイム (Go 製) |
| **Prometheus** | モニタリング・アラート (Go 製) |
| **Terraform** | IaC ツール (Go 製) |
| **Istio** | サービスメッシュ (Go 製) |
| **etcd** | 分散 KVS (Go 製) |
| **CockroachDB** | 分散 SQL データベース (Go 製) |

### 企業での採用事例

Uber, Amazon, HelloFresh などの小売・物流企業が、高速でスケーラブルなバックエンドインフラに Go を採用。100 万人以上の開発者がクラウド環境で Go を使用している。

### マイクロサービス領域のトレンド

- **gRPC + Protocol Buffers**: Go のマイクロサービス間通信の標準的選択肢として定着
- **OpenTelemetry**: 分散トレーシング・メトリクス収集での Go SDK の採用が拡大
- **Kubernetes Operators**: Go による Kubernetes Operator の開発が活発。AI 推論ワークロード管理の KubeAI なども登場

## まとめ

2025〜2026年の Go 言語は、**安定性と実用性**を軸に着実な進化を遂げている。

- **言語機能**: ジェネリクスの成熟 (型エイリアス対応)、`new` 関数の拡張など、控えめだが実用的な改善
- **パフォーマンス**: Green Tea GC のデフォルト化により GC オーバーヘッド 10〜40% 削減。cgo 30% 高速化、SIMD サポートの実験的導入
- **セキュリティ**: ポスト量子暗号 (ML-KEM)、FIPS 140-3 ネイティブ対応で規制産業向けの準備が整備
- **AI/ML**: Ollama・LangChainGo を中心に推論インフラ層での存在感が拡大
- **エコシステム**: Gin が Web フレームワークの約半数のシェアを獲得。slog が標準ロギングの新基準に
- **コミュニティ**: 開発者数 580 万人超、プライマリ言語利用者は 5 年で 2 倍に成長

Go は「退屈で信頼できる言語」としてのポジションを確立し、クラウドネイティブ・バックエンド・インフラの基盤言語としての地位をさらに強固にしている。
