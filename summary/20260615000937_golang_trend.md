# Go言語トレンドサマリー（2025〜2026年）

調査日: 2026-06-15

---

## 1. 最新リリース状況

### Go 1.23（2024年8月リリース）

- **Range-over-func イテレータ**: `for-range`ループでイテレータ関数を直接使用可能に（Go 1.22で実験的導入、1.23で正式化）
- **`iter`パッケージ**: ユーザー定義イテレータの基本型（`iter.Seq[V]`、`iter.Seq2[K,V]`）を提供
- **`unique`パッケージ**: 値のインターニング（正規化）によるメモリ効率の向上
- **`structs`パッケージ**: `HostLayout`型による構造体レイアウトの制御
- **slices/mapsパッケージ拡張**: `All`、`Values`、`Chunk`、`Sorted`など、イテレータ対応の関数群を追加
- **Timer/Tickerの改善**: チャンネルをアンバッファに変更、GCによる自動クリーンアップ
- **Goテレメトリ**: オプトイン方式の使用統計収集システム
- **ジェネリック型エイリアスのプレビュー**: `GOEXPERIMENT=aliastypeparams`で実験的に有効化

### Go 1.24（2025年2月リリース）

- **ジェネリック型エイリアスの正式化**: 型エイリアスにも型パラメータを付与可能に（Go 1.23から昇格）
- **Swiss Tablesベースの新map実装**: マイクロベンチマークで最大60%高速化、CPU負荷を平均2〜3%削減
- **小オブジェクトのメモリアロケーション最適化**: 新しいランタイム内部mutexの実装
- **`go get -tool`**: go.modの`tool`ディレクティブでモジュール内のツール依存関係を追跡（tools.goワークアラウンドの廃止）
- **`weak`パッケージ**: `weak.Pointer[T]`型による弱参照。キャッシュや正規化マップの構築に活用
- **`os.Root`型**: ディレクトリ制限付きファイルシステムアクセス。サンドボックス環境での安全なファイル操作
- **`runtime.AddCleanup`**: `runtime.SetFinalizer`に代わる柔軟で効率的なファイナライズ機構
- **`testing.B.Loop`**: `for b.Loop() { ... }`構文による新しいベンチマークイテレーション
- **`encoding/json`の`omitzero`タグ**: Goのゼロ値（`omitempty`とは異なる）でフィールドを省略
- **WebAssembly対応強化**: `go:wasmexport`ディレクティブ、WASIリアクター/ライブラリビルドのサポート
- **ポスト量子暗号**: `crypto/mlkem`（ML-KEM-768/ML-KEM-1024）、`crypto/hkdf`、`crypto/pbkdf2`、`crypto/sha3`を追加
- **FIPS 140-3対応**: `GOFIPS140`環境変数と`fips140` GODEBUG設定による制御
- **`testing/synctest`（実験的）**: `GOEXPERIMENT=synctest`で有効化。仮想時間による並行コードテスト

### Go 1.25（2025年8月リリース）

- **実験的ガベージコレクタ（Green Tea GC）**: `GOEXPERIMENT=greenteagc`で有効化。小オブジェクトのマーキング/スキャンの局所性とCPUスケーラビリティを改善。GCオーバーヘッド10〜40%削減
- **`encoding/json/v2`（実験的）**: `GOEXPERIMENT=jsonv2`で有効化。JSON APIの大幅刷新。デフォルトでcase-sensitiveマッチング
- **`testing/synctest`が正式GA化**: 仮想時間を用いた決定的な並行コードテスト。`Run`と`Wait`関数を提供
- **コンテナ対応GOMAXPROCS**: cgroupのCPU帯域幅制限を自動検出し、GOMAXPROCSをリミットに合わせて設定。動的な更新にも対応
- **`runtime/trace.FlightRecorder`**: インメモリリングバッファへの継続的トレース記録。重要イベント発生時にスナップショットを取得可能
- **DWARF 5デバッグ情報**: デバッグ情報のサイズ削減とリンク時間の短縮（特に大規模バイナリ）
- **go.modの`ignore`ディレクティブ**: 指定ディレクトリをgoコマンドの処理対象から除外
- **Core Types概念の除去**: ジェネリクス仕様の簡素化。各言語機能が独自のルールを定義する方式に移行

### Go 1.26（2026年2月リリース）

- **Green Tea GCがデフォルト有効化**: GCオーバーヘッド10〜40%削減。新しいamd64 CPU（Intel Ice Lake、AMD Zen 4+）ではベクトル命令活用で追加約10%改善
- **`new`関数の拡張**: 初期値式を渡せるように（`new(int, 42)`のような構文）
- **ジェネリック型の自己参照**: ジェネリック型が自身の型パラメータリストで自分自身を参照可能に（再帰的型パラメータ）
- **cgoオーバーヘッド約30%削減**
- **スライスのスタックアロケーション最適化**: コンパイラがより多くの状況でスライスのバッキングストアをスタック上に配置
- **`go fix`コマンドの刷新**: Go解析フレームワークベースに書き直され、約20以上の「modernizer」を搭載。`//go:fix inline`アノテーションによるインライン化も対応
- **`errors.AsType[E]`**: ジェネリクスを活用した型安全なエラーアサーション。`errors.As`のリフレクション不要版
- **`runtime/secret`（実験的）**: 暗号処理後の機密データ（レジスタ、スタック、ヒープ）を安全に消去
- **ゴルーチンリーク検出（実験的）**: `GOEXPERIMENT=goroutineleakprofile`でGCマーキングフェーズを利用した到達不能ゴルーチンの検出
- **新パッケージ**: `crypto/hpke`（RFC 9180準拠 HPKE）、`crypto/mlkem/mlkemtest`、`testing/cryptotest`
- **`simd/archsimd`（実験的）**: アーキテクチャ固有SIMD組み込み関数。ベンチマークで最大**26倍**の高速化

### Go 1.27（今後のリリース予定）

- **ジェネリックメソッド**: `GOEXPERIMENT`として確認済み。メソッドが型レベルだけでなく独自の型パラメータを持てるように。Go ジェネリクスの最大の欠点の一つを解消する見込み

- **v0.20.0（2025年7月）**: 実験的MCPサーバーを内蔵。AIアシスタントにGo固有のツールを公開（`go_diagnostics`、`go_references`、`go_rename_symbol`、`go_vulncheck`等）

- v0.21.0（2025年12月）でさらなる改善

### Delve デバッガ

- v1.26.x（2026年）: Go 1.26サポート、Windows arm64完全サポート
- MCPサーバー対応が進行中: AIエージェントがDAPを通じてライブプログラムをデバッグ可能に

### パッケージマネジメント

- Go 1.24の`tool`ディレクティブでプロジェクト内ツール依存管理を標準化
- Go 1.25の`ignore`ディレクティブでモノレポ開発のワークフローを改善
- Go 1.25よりGo配布にプリビルドツールバイナリを削減、`go tool`で必要時にオンデマンドビルド

## 7. セキュリティ

### ポスト量子暗号対応

| バージョン | 対応内容 |
|-----------|---------|
| Go 1.24 | ML-KEM-768/1024（FIPS 203準拠）、X25519MLKEM768鍵交換デフォルト有効、crypto/tlsで弱い暗号を自動ブロック |
| Go 1.26 | `crypto/hpke`（RFC 9180 HPKE）、`crypto/mlkem/mlkemtest`、`testing/cryptotest` |

### FIPS 140-3

- Go 1.24でPure GoによるFIPS 140-3モードを搭載
- `GOFIPS140`環境変数（ビルド時）と`fips140` GODEBUG設定（ランタイム）で制御
- Go+BoringCrypto統合を置き換える正式なFIPS対応ソリューション

### セキュリティ監査

- Go暗号ライブラリの第三者セキュリティ監査（Trail of Bits）が実施・公開済み
- 発見された脆弱性は1件のみ（ppc64/ppc64leでのECDSAタイミングサイドチャネル、CVE-2025-22866）
- Pure Go実装の堅牢性が確認され、Go+BoringCrypto統合の廃止を後押し

### govulncheck

- Go公式の脆弱性スキャンツール。静的解析により到達可能なコードパスの脆弱性のみを報告
- SARIF/OpenVEX出力形式をサポート（CI/CD統合向け）
- 脆弱性データベース: 2025年に標準ライブラリで9件、2026年（6月まで）に17件を追跡

### サプライチェーンセキュリティ

- **2025年2月**: Goモジュールミラーキャッシュを悪用した悪意のあるパッケージが発見（タイポスクワッティング）
- **2025年5月**: ディスクを消去するマルウェアを含むGoモジュールが検出
- **2025年6月**: GitLabが偽のMongoDB Goドライバーによるサプライチェーン攻撃を検出・ブロック
- **2025年12月**: GitHub DependabotがGo依存関係グラフをネイティブサポート開始
- 学術研究: GoLeash（CCS 2025）によるランタイムポリシー適用、GoSurfによる攻撃面分析

## 9. 今後の注目ポイント

1. **Go 1.27 ジェネリックメソッド**: メソッドレベルの型パラメータが`GOEXPERIMENT`として確認済み。ジェネリクスの最大の制限を解消する重要な進展
2. **エラーハンドリング構文の公式クローズ**: 2025年6月、Goチームはエラーハンドリングの構文変更提案を**今後追求しない**と正式発表。7年間で3つの提案（check/handle、try()、?演算子）がいずれもコンセンサスに至らず。`if err != nil`パターンは永続的にGoの標準として残る
3. **パターンマッチング / Sum Types**: Developer Surveyでも上位の要望。Sum types提案（#76920）が2025年12月に提出されたが、採用は当面見込まれない
4. **JSON v2の正式化**: Go 1.25で実験的に導入された`encoding/json/v2`の安定版リリースが期待される
5. **AI/MCPエコシステムの成熟**: 公式MCP SDKの安定化、gopls MCP統合、Delve MCPサーバー対応により、GoによるAIエージェント基盤が急速に整備中
6. **Green Tea GCのさらなる最適化**: SIMD活用の拡大やワークロード特化チューニングによるレイテンシ・スループット向上
7. **SIMD組み込み関数**: Go 1.26で実験的導入された`simd/archsimd`の正式化が注目
