# Go言語トレンドサマリー (2026年6月)

## 1. 最新リリース

### Go 1.24 (2025年2月)

- **Generic型エイリアス**: 型エイリアスにジェネリクスのパラメータを適用可能に
- **go.modのtoolディレクティブ**: 実行可能な依存関係をモジュールで追跡可能に（従来の`tools.go`ワークアラウンドが不要に）
- **Swiss Tablesマップ実装**: 組み込み`map`をSwiss Tableベースに刷新。CPU・メモリオーバーヘッドを大幅削減（Datadogはマップメモリを約70%削減と報告）
- **FIPS 140-3準拠**: 内部Go暗号モジュールによる透過的なFIPSコンプライアンス
- **ポスト量子暗号**: `X25519MLKEM768`鍵交換がデフォルトで有効化
- **testing/synctest（実験的）**: フェイクロックによる決定論的な並行テスト
- **os.Root**: 特定ディレクトリにスコープされたファイルシステム操作
- **パフォーマンス**: ベンチマーク全体で2-3%のCPUオーバーヘッド削減、GCインクリメンタルポーズタイム15-25%改善

### Go 1.25 (2025年8月)

- **言語変更なし** — 安定性を重視
- **Green Tea GC（実験的）**: 新GC設計。小オブジェクトのローカリティとCPUスケーラビリティが向上し、GCオーバーヘッドを10-40%削減
- **encoding/json/v2（実験的）**: JSONパッケージの大幅刷新。デコード速度2-10倍向上、デフォルトでcase-sensitiveマッチング、無効なUTF-8と重複キーの拒否
- **testing/synctest正式化**: 実験的ステータスから一般提供へ昇格
- `go doc -http`オプションでブラウザ上のドキュメントサーバー起動が可能に

### Go 1.26 (2026年2月)

- **言語変更**:
  - `new()`組み込み関数が初期値式をサポート（例: `new(42)`で42を指す`*int`を作成）
  - **自己参照ジェネリック型**: 自身の型パラメータリスト内で自分自身を参照可能に
- **Green Tea GCがデフォルト有効化**（実験的から正式採用）
- **cgoオーバーヘッド約30%削減**
- **スライスバッキングストアのスタック割り当て**: より多くのケースでスタック割り当てが可能に
- **go fix刷新**: Goアナリシスフレームワーク上で書き直され、約24の「modernizer」が非推奨パターンを自動的に書き換え
- **実験的SIMDパッケージ** (`simd/archsimd`): amd64向けアーキテクチャ固有のSIMD命令（128/256/512ビットベクトル型）。`GOEXPERIMENT=simd`で有効化
- **新パッケージ**: `crypto/hpke`, `crypto/mlkem/mlkemtest`, `testing/cryptotest`

## 2. 注目の言語機能・プロポーザル

### ジェネリックメソッド (Go 1.27ターゲット)

2026年3月、Robert Griesemer氏によるメソッドへの型パラメータ追加提案が承認された。Go 1.18でジェネリクスが導入されて以来、長年拒否されてきた機能が遂に実現へ。GitHub issueには900以上のポジティブリアクションが付き、Go 1.27（2026年8月）での実装を目指している。

### エラーハンドリング構文 — 正式に棚上げ (2025年6月)

7年間で3回の試み（Rustに触発された`?`演算子提案を含む）を経て、Go チームはエラーハンドリングの構文変更の追求を中止すると発表。`if err != nil { return err }`パターンが永続的な標準として確定。

### Core types概念の削除 (Go 1.25)

Go 1.18で導入された「core types」概念が仕様から削除され、明示的な散文に置き換えられた。より強力なスライス操作と改善された型推論への道を開いた。

## 7. ベストプラクティスの変化

### 構造化ロギング (slog)

`log/slog`が新標準。`slog.With()`によるコンテキスト付きロギングと`context.Context`経由のロガー渡しがベストプラクティス。テスタビリティの観点からDI（依存性注入）が推奨。

### イテレーターのファーストクラス化

Go 1.23以降、カスタムイテレーター関数がカスタムコレクションの走査の標準的な方法に。チャネルベースのイテレーションを置き換え。

### go fixによるコード近代化

Go 1.26から`go fix`実行がコードベースを最新の言語機能・非推奨API置き換えに対応させる標準的な実践に。

### OpenTelemetryのデフォルト化

Goサービスへのトレース・メトリクス・ログのOpenTelemetry計装が最初から標準化。

### synctestによる並行テスト

`testing/synctest`が一般提供となり、並行コードの決定論的テストの推奨手法に。

### json/v2への準備

`encoding/json/v2`の実験的評価を開始することが推奨。将来的にv1をデフォルトとして置き換える予定。
