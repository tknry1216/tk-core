# Go言語トレンドサマリー

**更新日時:** 2026年6月11日

---

## 1. 最新リリース状況

### Go 1.26（2026年2月リリース）

Go 1.26 は2026年2月にリリースされ、言語仕様・パフォーマンス・セキュリティの各面で大幅な改善が行われた。

#### 言語仕様の変更

- **`new(expression)` 構文**: `new` 関数が式を受け取れるようになり、初期値付きポインタを簡潔に生成可能（例: `new(42)` で `*int` を返す）。JSON やProtocol Buffer のオプショナルフィールドで特に有用
- **ジェネリック型の自己参照（F-bounded polymorphism）**: ジェネリック型が自身の型パラメータリスト内で自己参照できるようになり、`type Adder[A Adder[A]] interface { Add(A) A }` のような複雑なデータ構造が表現可能に
- **`errors.AsType[T]`**: `errors.As` のジェネリック版。型安全なエラー抽出を提供し、単一ラップエラーで約10倍高速・ゼロアロケーション。ポインタのボイラープレートと不正な型による runtime panic を排除

#### パフォーマンス改善

- **Green Tea GC がデフォルト有効化**: Go 1.25 で実験的に導入された新ガベージコレクタがデフォルトに。メモリをスパン単位でスキャンし、CPU キャッシュ効率を大幅改善。GC の CPU コストを **10〜40%** 削減
- **cgo オーバーヘッド約30%削減**: ネイティブコードとの相互呼び出しが高速化
- **スライスのスタック割り当て最適化**: コンパイラがより多くの状況でスライスのバッキングストアをスタックに配置可能に
- **小オブジェクト割り当て最大30%高速化**: サイズ特化のメモリ割り当てルーチンを生成

#### 新パッケージ・ツール

- **`crypto/hpke`**: Hybrid Public Key Encryption（RFC 9180）、ポスト量子ハイブリッド KEM 対応
- **`crypto/mlkem/mlkemtest`、`testing/cryptotest`**: 暗号テスト用の新パッケージ
- **実験的 `simd/archsimd`**: amd64 アーキテクチャ向け SIMD 操作（128/256/512ビットベクタ型）。`GOEXPERIMENT=simd` で有効化
- **実験的 `runtime/secret`**: 秘密情報の安全な破棄が可能に
- **`go fix` 完全刷新**: Go analysis framework ベースに書き直され、数十の「モダナイザ」アナライザを搭載。コードを最新機能に安全に移行
- **`go tool cover -pkg`**: ホールプログラムモードのテストカバレッジを提供

### Go 1.25（2025年8月リリース）の主要機能（振り返り）

- **Green Tea GC（実験的）**: `GOEXPERIMENT=greenteagc` で有効化。8KiB スパン単位でメモリをスキャンし、CPU キャッシュ効率を改善
- **`encoding/json/v2`（実験的）**: `GOEXPERIMENT=jsonv2` で利用可能。アンマーシャリングが大幅高速化。不正 UTF-8 や重複キーをデフォルトで拒否
- **コンテナ対応 GOMAXPROCS**: コンテナの CPU リミットに基づいて自動設定。`uber-go/automaxprocs` が不要に
- **`testing/synctest`**: 仮想化された時計を用いた並行コードのテスト支援パッケージが GA
- **`WaitGroup.Go` メソッド**: ゴルーチン生成とカウントを簡潔に記述
- **Flight Recorder API**: ランタイムトレーシング用の新API

### Go 1.27（2026年8月リリース予定）

Go 1.27 のリリースフリーズは2026年5月20日に実施済み。主な新機能:

- **ジェネリックメソッド**: メソッド宣言で独自の型パラメータを宣言可能。2026年3月にプロポーザルが承認された、ジェネリクスの大きな進化。ただしインターフェースがジェネリックメソッドを要求することはまだ不可
- **`go mod tidy` の重複 require ブロック自動マージ**
- **小メモリ割り当て（<80バイト）のコスト最大30%削減**
- **macOS 13 Ventura 以降が必須に**

### エラーハンドリング構文に関する公式決定（2025年6月）

Go チームは **エラーハンドリングの構文的な言語変更の追求を正式に中止** することを発表。`?` 演算子や `try`/`check`/`handle` などの提案はすべてクローズされた。`if err != nil { return err }` パターンが引き続き標準であり続ける。

### ジェネリクスの進化まとめ

| バージョン | 機能 |
|---|---|
| Go 1.23 | ジェネリック型エイリアス（実験的プレビュー）、Range-over-func イテレータ安定化 |
| Go 1.24 | ジェネリック型エイリアス完全サポート |
| Go 1.25 | コアタイプ概念を仕様から除去（簡素化、動作変更なし） |
| Go 1.26 | 自己参照型パラメータ、`errors.AsType[T]` |
| Go 1.27（予定） | **ジェネリックメソッド**（メソッドが独自の型パラメータを持てる。ただしインターフェースメソッドは不可） |

## 2. パフォーマンス・ランタイムの進化

### Swiss Tables マップ実装（Go 1.24〜）

Go 1.24 で組み込み map の実装が Swiss Tables + 拡張可能ハッシュに全面刷新された。

- 8スロットのグループ単位で SIMD 並列比較を行い、マップ操作が **最大60%高速化**
- ロードファクタ向上（81.25% → 87.5%）でメモリ効率改善
- **Datadog の実例**: 350万要素で 726MiB → 217MiB（約70%削減）、フリート全体で数百GB の節約

### Profile-Guided Optimization（PGO）

- Go 1.25 以降、PGO は完全に安定化しビルドパイプラインに容易に統合可能
- 本番プロファイルを使ったビルドで **2〜14%のパフォーマンス向上**
- **Uber の事例**: PGO 導入により主要サービス全体で **24,000 CPU コア分の削減** を達成

### コンテナ対応 GOMAXPROCS（Go 1.25）

- コンテナの CPU リミットに基づいて GOMAXPROCS を自動設定
- `uber-go/automaxprocs` のようなサードパーティパッケージが不要に
- ランタイムが cgroup CPU 帯域制限を定期的に再評価

## 6. セキュリティ

### FIPS 140-3 ネイティブ対応（Go 1.24〜）

- Go 1.24 で標準ライブラリに FIPS 140-3 モジュールを組み込み
- **Module v1.0.0**: CAVP 証明書 A6650 取得。CMVP に提出済み
- **Module v2.0.0**: ML-DSA（ポスト量子デジタル署名）を実装。2026年4月28日時点で CMVP「Pending Review」
- `GODEBUG=fips140=on` で FIPS モード有効化、`fips140=only` で厳格準拠
- ポスト量子 ML-KEM 鍵交換（FIPS 203）も検証済み

### govulncheck

- 2026年4月22日に最新版公開。ソースコードの静的解析またはバイナリのシンボルテーブルから到達可能性分析を実施
- SARIF 出力対応で GitHub Code Scanning と統合可能
- IDE 統合（VS Code / gopls）も対応

### 暗号ライブラリ監査

- **Trail of Bits 監査（2025年）**: Google が委託。ECDH, ML-KEM, ECDSA, RSA, Ed25519, AES-GCM 等のコアパッケージを監査
- 発見された問題は1件のみ（ppc64/ppc64le での ECDSA 可変時間処理、CVE-2025-22866）
- 全体として非常にクリーンな監査結果

### サプライチェーンセキュリティ

- **BoltDB タイポスクワット事件**: 悪意あるモジュールが Go Module Proxy キャッシュ経由で3年以上存続。Go 脆弱性 DB に GO-2025-3451 として登録
- Go 脆弱性 DB が CVE だけでなく悪意あるパッケージもカバーするように拡張

## 7. 開発者ツール

### golangci-lint v2（最新: v2.12.2、2026年5月）

2025年3月にメジャー v2 リリース。主な変更:
- `enable-all`/`disable-all` を `linters.default` に置き換え
- `golangci-lint fmt` コマンドでコードフォーマット
- `golangci-lint migrate` で v1→v2 設定の自動変換
- 100以上のリンターを統合。Kubernetes, Prometheus, Terraform が採用

### gopls（Go Language Server）

- **v0.20.0（2025年7月）**: 実験的 **MCP サーバー** を搭載し、AI アシスタントから gopls 機能を利用可能に。`ignoredError` inlay hint でエラー破棄の検出。永続パッケージインデックスがデフォルト有効化
- **v0.18.0（2025年2月）**: コードモダナイゼーション提案（if/else → min/max 等）。ジェネリクスの「Go to Implementations」完全対応
- リリースサイクル: マイナー約3ヶ月ごと、パッチは月次

### templ（型安全 HTML テンプレート）

- 最新版 2026年5月10日公開。`.templ` ファイルを Go コードにコンパイルし、型エラーをコンパイル時に検出
- コンポーネントベースで HTMX との組み合わせが急成長中

### log/slog（標準ライブラリ）

- Go 1.21 以降の標準構造化ロギング。新規プロジェクトの推奨選択肢
- zap/zerolog のハンドラをプラグイン可能

- 2025年9月に実施、5,379人が回答。満足度 **91%**（うち「非常に満足」が約2/3）
