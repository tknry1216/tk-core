# Go言語トレンドサマリー

**更新日時:** 2026年5月10日

## 直近のリリース履歴

### Go 1.23（2024年8月）

- **Range over function types**: for-rangeループがユーザー定義イテレータ関数（`func(func(K) bool)`）に対応。カスタムイテレータの実装が容易に
- 新パッケージ `iter` の追加（イテレータの基本定義）
- `slices`・`maps` パッケージにイテレータ対応関数を追加

### Go 1.24（2025年2月）

- **Swiss Table maps**: 組み込みmapの内部実装をGoogle発のSwiss Tableに刷新。マップ操作が約60%高速化、大規模マップのメモリ使用量が約70%削減（Datadogは数百GBのメモリ節約を報告）
- **ジェネリック型エイリアス**: 型エイリアスがパラメータ化可能に
- **go.modの`tool`ディレクティブ**: 実行可能な依存関係をモジュールで追跡。従来の`tools.go`ワークアラウンドが不要に
- **FIPS 140-3準拠**: FIPS承認済み暗号アルゴリズムの透過的利用メカニズム
- **ポスト量子暗号**: X25519MLKEM768鍵交換をデフォルト有効化
- **`os.Root`型**: ディレクトリスコープ付きファイルシステム操作
- **`testing/synctest`（実験的）**: フェイククロックによる並行コードのテスト支援
- **`runtime.AddCleanup`**: `SetFinalizer`を置き換える新ファイナライゼーション機構
- **WebAssembly改善**: `go:wasmexport`ディレクティブ、WASIリアクター/ライブラリサポート

### Go 1.25（2025年8月）

- **Green Tea GC（実験的）**: `GOEXPERIMENT=greenteagc`で有効化。ページ/スパンレベルで動作し、一般的なワークロードでGC時間を10%削減、最大40%削減のケースも。Google内部で本番利用
- コンテナ環境でのGOMAXPROCS自動認識改善
- `go mod ignore`ディレクティブの追加

## Go 1.26 リリース（2026年2月）

Go 1.26が2026年2月10日にリリースされた。言語仕様の改善、パフォーマンスの大幅な向上、セキュリティ強化が図られている。

### 言語仕様の変更

- **`new` 関数の拡張**: 組み込み `new` 関数がオペランドとして式を受け付けるようになり、変数の初期値を指定可能に
- **ジェネリクスの自己参照**: ジェネリック型が自身の型パラメータリスト内で自己参照可能に。複雑なデータ構造やインターフェースの実装が簡素化

### パフォーマンス改善

- **Green Tea GC**: 以前は実験的だったGreen Teaガベージコレクタがデフォルトで有効化
- **cgoオーバーヘッド削減**: ベースラインのcgoオーバーヘッドが約30%削減
- **スタックアロケーション最適化**: コンパイラがスライスのバッキングストアをスタックに割り当てられるケースが拡大

### セキュリティ強化

- **ヒープベースアドレスのランダム化**: 64ビットプラットフォームで、ランタイムが起動時にヒープベースアドレスをランダム化。cgo使用時の攻撃耐性向上
- **ポスト量子鍵交換**: TLSでハイブリッドポスト量子鍵交換（古典的楕円曲線暗号 + ML-KEM）がデフォルトで有効化。「harvest now, decrypt later」攻撃への対策
- **`runtime/secret` パッケージ（実験的）**: 暗号コードで使用される一時データの安全な消去機能

### ツーリング

- **`go fix` コマンドの刷新**: Go分析フレームワークを使用して完全に書き直され、数十の「modernizers」（モダナイザー）を搭載。コードベースを最新のイディオムやコアライブラリAPIに安全にアップデート可能
- **goroutineリークプロファイル（実験的）**: `runtime/pprof` パッケージに `goroutineleak` プロファイルタイプが追加

### 実験的機能

- **`simd/archsimd` パッケージ**: SIMD操作へのアクセスを提供する実験的パッケージ

## 市場動向・人気度

### 統計データ

- **Stack Overflow Developer Survey**: Go は世界の開発者の13.5%が使用
- **TIOBE Index**: 2025年4月時点で7位（Go史上最高順位）
- **API利用率**: GoがNode.jsを抜き、自動化APIリクエストで最も使用される言語に（全APIコールの12%、前年の8.4%から上昇）

### 2025 Go Developer Survey（2026年1月公開）

- 回答者数: 5,379名のGo開発者（91%がGoでの開発に満足と回答）
- **主な用途**: CLIツール（74%）、API/RPCサービス（73%）、ライブラリ/フレームワーク（49%）
- **AI ツール利用状況**: 83%がAIツールを何らかの形で活用。ただし満足度は55%にとどまり（「とても満足」はわずか13%）、53%が「生成コードが動作しない」と回答
- **開発者の課題**: ベストプラクティス/イディオムの把握（33%）、他言語にある機能の不足（28%）、信頼できるモジュールの発見（26%）
- **推定Go開発者数**: 世界で約410万人（JetBrains推計）
- **今後の採用予定**: 全開発者の11%が今後12ヶ月以内にGoを採用予定

### 注目の新興フレームワーク

- **Encore.go**: 分散システム向けモダンバックエンドフレームワーク。インフラ自動化、オブザーバビリティ、自動サービスディスカバリを内蔵

## AI・機械学習領域での台頭

2026年はGoがAI開発で本格的に注目を集める転換期となっている。

### Go AI Agentフレームワーク

| フレームワーク | 特徴 |
|---|---|
| **ADK (Agent Development Kit)** | エンタープライズ向け |
| **Genkit** | ラピッドプロトタイピング |
| **LangChain Go** | 柔軟なライブラリ |
| **Eino** | Go ネイティブ設計 |
| **Anyi** | 特化型ソリューション |

### MCP（Model Context Protocol）エコシステム

- **公式 Go MCP SDK** (`golang.org/x/tools`): v1.2.0（2026年1月）。MCPサーバー/クライアントの構築用
- **gopls MCP サーバー**: Go言語サーバーにMCPサーバー機能が実験的に統合。AIアシスタントにGoの知見を提供
- **mcp-go（コミュニティ）**: MCPスペックの実装。マルチバージョン後方互換性対応

### なぜGoがAIツーリングで選ばれるか

- 高い並行処理性能（goroutine）
- スケーラブルなインフラ統合
- 低レイテンシ・高スループット
- シングルバイナリデプロイの容易さ

- パッケージインデックスの永続化により、Organize ImportsやImport補完が桁違いに高速化
