### Go 1.26（2026年2月リリース）
Go 1.26 が2026年2月にリリースされ、言語仕様の改善、パフォーマンスの大幅な向上、開発者体験の向上が図られた。2026年3月5日には Go 1.26.1 がリリースされ、暗号化・HTMLテンプレート・URLパッケージ等のセキュリティ修正が含まれている。

- **`runtime/secret` パッケージ（実験的）**: 秘密情報の安全な破棄が可能に
- **`go mod init`** で生成される `go directive` の値が Go 1.26 から変更

### Go 1.25（2025年8月リリース）
- **`testing/synctest` パッケージ**: 並行処理コードのテストを支援する新パッケージ。仮想化された時間の中でテスト関数を隔離された「バブル」内で実行可能
- **`WaitGroup.Go` メソッド**: goroutine の生成・カウントパターンをより便利に
- **`encoding/json/v2`（実験的）**: `GOEXPERIMENT=jsonv2` で有効化できる新しいJSON実装。デコードベンチマークで2〜10倍の高速化、ストリーミング対応、細粒度の設定オプション（`OmitZeroStructFields`、`FormatNilMapAsNull` 等）を提供
- **DWARF v5 対応**: コンパイラ・リンカがデバッグ情報を DWARF version 5 で生成し、バイナリサイズを削減
- **`go build -asan` 強化**、**`go mod ignore` ディレクティブ**追加、**`go doc -http` サーバー**新設
- **コンテナ対応 GOMAXPROCS**: コンテナ環境でのCPUリソース認識が改善
- **実験的 GC・FlightRecorder** の追加

### Go 1.24（2025年2月リリース）
- **ジェネリック型エイリアス**: 型エイリアスが定義型と同様にパラメータ化可能に
- **`go.mod` の `tool` ディレクティブ**: 実行可能依存関係をモジュールで管理可能に（旧 `tools.go` ブランクインポート不要に）
- **Encrypted Client Hello (ECH)**: TLSサーバーがECHをサポート
- **ポスト量子暗号 X25519MLKEM768**: 新しい鍵交換メカニズムがデフォルトで有効
- **`runtime.AddCleanup`**: `runtime.SetFinalizer` より柔軟で効率的なファイナライゼーション機構
- **`weak` パッケージ**: メモリ効率の良いデータ構造のための弱参照プリミティブ
- **`go:wasmexport` ディレクティブ**: Go プログラムから WebAssembly ホストへの関数エクスポートが可能に
- **`omitzero` JSON構造体タグ**: JSONマーシャリングの新オプション
- **`T.Chdir` / `B.Chdir` メソッド**: テスト・ベンチマーク中の作業ディレクトリ変更を簡素化

各LLMプロバイダの公式Go SDKも活発に開発中: Anthropic Go-SDK、openai-go、Google go-genai

### WebAssembly
- `go:wasmexport` ディレクティブにより、Go から Wasm 関数のエクスポートが可能に
- WASI Preview 1（`wasip1`）をサポート済み。**WASIp3** サポートの提案が進行中（GitHub issue #77141）
- WASIp3 は Go にとって重要: goroutine が他の goroutine をブロックせずに I/O でブロックできる初の WASI マイルストーン
- WASI 1.0 は2026年末〜2027年初頭に予定
- ブラウザ外の Wasm ランタイム（Wazero、WasmEdge）でのGoの利用が拡大

## コミュニティ動向

### 国内イベント

### クラウドネイティブ基盤
Go はクラウドネイティブインフラの支配的言語であり続けている:
- **Kubernetes オペレーター**: Operator Framework、Kubebuilder、controller-runtime による開発
- **Crossplane**: Kubernetes をユニバーサルコントロールプレーンに変換（Go 製）
- **Cilium**: eBPF ベースのネットワーキング・オブザーバビリティ（Go 製）
- **サービスメッシュ**: Istio、Linkerd（いずれも Go ベース）

### アーキテクチャパターン
- **ヘキサゴナルアーキテクチャ（ポート&アダプター）**: ドメイン・アプリケーション・アダプター層の明確な分離。DDD との組み合わせで強いトラクション
- **モジュラーモノリス**: DDD + ヘキサゴナルアーキテクチャをモノリス内で適用し、将来的なマイクロサービス分離を見据える実践的パターン
- **イベント駆動アーキテクチャ**: NATS、Kafka、RabbitMQ、AWS SQS との組み合わせが人気
- **DDD（ドメイン駆動設計）**: Aggregate、Entity、Value Object、Domain Event を用いた大規模プロジェクトでの適用が増加
