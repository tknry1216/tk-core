# Go言語トレンドサマリー（2026年6月時点）

## 1. 最新リリース状況

### Go 1.24（2025年2月リリース）
- **Generic Type Aliases**: 型エイリアスにジェネリクスのパラメータを持たせることが可能に。パッケージ間の型移動時に後方互換性を維持しやすくなった
- **Weak Pointers**: `weak`パッケージの追加。弱参照によりGCが不要なオブジェクトを解放可能。キャッシュや正規化マップに活用
- **Swiss Tables**: 組み込みmapの内部実装をSwiss Tableベースに刷新。大規模mapのアクセス/代入が最大30〜35%高速化、イテレーションが10〜60%高速化
- **runtime.AddCleanup**: `SetFinalizer`に代わる新しいファイナライゼーション機構。複数クリーンアップの登録、内部ポインタへのアタッチ、循環参照時のリーク防止に対応
- **WebAssemblyサポート強化**: Wasmビルドの改善
- **全体パフォーマンス**: ランタイム改善によりCPUオーバーヘッドが平均2〜3%削減

### Go 1.25（2025年8月リリース）
- **GOMAXPROCS改善**: Linuxにおいてcgroupの CPU帯域幅制限を考慮するようデフォルト動作を変更。コンテナ環境での最適化が自動的に効くように
- **実験的JSON v2**: `GOEXPERIMENT=jsonv2`で新しいJSON実装を試用可能
- **Green Tea GC（実験的）**: `GOEXPERIMENT=greenteagc`でオプトイン。GCオーバーヘッドの大幅削減を目指す新ガベージコレクタ
- 言語仕様の変更はなし

### Go 1.26（2026年2月リリース / 最新安定版）
- **Green Tea GCがデフォルト有効化**: GCヘビーなサービスで10〜40%のGCオーバーヘッド削減
- **`new(expression)`構文**: `new`関数がオペランドとして式を受け取り、初期値を指定可能に
- **自己参照ジェネリクス**: `Node[N Node[N]]`のような再帰的な型パラメータが許可
- **cgoオーバーヘッド約30%削減**
- **`go fix`コマンドの刷新**: Go分析フレームワークベースで書き直され、数十の「modernizer」を搭載。新機能を活用したコードへの自動修正を提案
- **実験的SIMDパッケージ**: `simd/archsimd`でSIMD命令に直接アクセス
- **実験的goroutineリークプロファイル**: GCを使ったgoroutineリーク検出機能
- **crypto/hpke**: HPKEの標準ライブラリ対応
- **runtime/secret（実験的）**: 暗号処理における一時データの安全な消去
- **linux/riscv64でrace detector対応**
- **セキュリティ修正**: Go 1.26.4（2026年6月2日）でcrypto/x509, mime, net/textprotoのセキュリティ修正

## 2. AI/LLMエコシステムの急成長

### 開発者のAI活用状況
- Go開発者の**70%以上**がAIアシスタントを定期的に利用（2025年調査）
- 50%以上が**毎日複数回**AIツールを使用
- Goのシンプルさ・構造の明確さがLLMベースのコード生成と好相性

### 主要LLM/AIライブラリ・フレームワーク
| ライブラリ | 概要 |
|---|---|
| **Ollama** | Go製のLLMモデルサービング。llama.cppバックエンドでローカルLLM実行 |
| **LangChain-Go** | PythonのLangChainのGoポート |
| **GenKit** | Google提供の統一AI APIフレームワーク |
| **Lingoose** | LLMアプリケーション構築の柔軟なフレームワーク |
| **BricksLLM** | モニタリングとアクセス制御 |
| **any-llm-go** | Mozilla製。OpenAI/Claude/Mistral等を統一インターフェースで利用 |
| **Google ADK for Go** | GoogleのAgent Development Kit。Go対応を発表 |

### Goの強み
- REST/RPC、高並行性、低レイテンシのインフラ構築に最適
- LLMエコシステムの基盤（推論サーバー、APIゲートウェイ等）としてPythonと棲み分け
- 課題: ベクトルDB、評価ツール等はPythonエコシステムが依然優位

## 3. Webフレームワーク動向

### シェアと特徴（2025〜2026年）
| フレームワーク | シェア | 特徴 |
|---|---|---|
| **Gin** | **48%** | 最も成熟。ミドルウェアエコシステムが最大。JWT・Prometheus・OpenTelemetry対応 |
| **Echo** | **16%** | Ginより洗練されたAPI。バリデーション・テンプレーティング等を組み込みで提供 |
| **Fiber** | **11%** | Fasthttp基盤で約130k req/sec。Express.jsライクなAPI。JS→Go移行者に人気 |
| **Chi** | - | 標準`net/http`互換の軽量ルーター。ミドルウェアの再利用性が高い |
| **gorilla/mux** | **17%→低下中** | アーカイブ化後シェア減少 |

### 2026年のトレンド
- フレームワークの**専門化**が進行（汎用→特定ユースケース特化）
- Fiberの急成長が継続するも、Fasthttp依存によるHTTP/2非対応や標準ライブラリ非互換がトレードオフ

## 4. クラウドネイティブ・インフラ

### Goの支配的地位
- Kubernetes, Docker, Terraform, Prometheus, Istio等の主要クラウドインフラがGo製
- GitHub Octoverseで**2024年3番目に急成長**した言語（Python, TypeScriptに次ぐ）
- **開発者の11%**が今後12ヶ月以内にGoの採用を計画

### WebAssembly（Wasm）との統合
- Wasm実行のコールドスタートレイテンシ: コンテナの数百msから**数ミリ秒**に短縮
- メモリフットプリントが**1桁小さく**（MB→KB）
- Kube-Wasmプロジェクトを通じたKubernetes環境でのWasm実行が進展

### プラットフォームエンジニアリング
- Internal Developer Platform (IDP)の構築にGoが活用
- セルフサービスAPI、Kubernetes CRD経由でインフラの抽象化を提供

## 5. セキュリティ・サプライチェーン

### 主な動き
- **サプライチェーン攻撃の顕在化**: BoltDBのtyposquat攻撃、偽MongoDB Goドライバーなどの事例
- **govulncheck**: CI/CDパイプラインでの脆弱性スキャンツール。実際に呼び出される脆弱な関数を特定
- **Capslock**: Google発のケイパビリティ分析ツール
- **FIPS 140準拠**: `GOFIPS140=v1.0.0`でビルド、`GODEBUG=fips140=on`で有効化
- **Trail of Bits監査**: Go暗号ライブラリの第三者監査が完了

### 頻繁なセキュリティリリース
- 2025年10月に1回のリリースで10件のセキュリティ修正（年間最大）
- 主にDoS系の中程度の脆弱性が中心
