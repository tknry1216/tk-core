## Go 1.27 リリース予定（2026年8月）

Go 1.27 が2026年8月にリリース予定。長年待望されていた**ジェネリックメソッド**がついに導入され、Go のジェネリクス機能が大きく拡張される。

### 主要な言語変更

- **ジェネリックメソッド**: メソッド宣言で独自の型パラメータを宣言可能に。特定のデータ型の名前空間内にジェネリック関数を追加できるようになった。ただし、インターフェースのメソッドは型パラメータを宣言できず、ジェネリックメソッドでインターフェースメソッドを実装することもできない
- **構造体リテラルのキー拡張**: 構造体リテラルのキーにトップレベルのフィールド名だけでなく、任意の有効なフィールドセレクタを使用可能に
- **関数型推論の汎用化**: ジェネリック関数をマッチする関数型の変数に代入（または変換）するすべてのコンテキストで型推論が適用されるように

### ツールチェーンの改善

- `go mod tidy` が重複する `require` ブロックを自動マージ（go 1.27以降のモジュール）
- `go fix` に新しいモダナイザー追加（`atomictypes`, `embedlit`, `slicesbackward`, `unsafefuncs`）
- `go doc` が `package@version` 構文をサポート（例: `go doc example.com/pkg@v1.2.3`）
- レスポンスファイル（`@file`）パースが `compile`, `link`, `asm`, `cgo`, `cover`, `pack` ツールでサポート

### その他の変更

- Unicode 15 から Unicode 17 へアップグレード
- macOS 13 Ventura 以降が必須に
- Linux ppc64 ポートで ELFv2 ABI を採用

## Go 1.26 の振り返り（2026年2月リリース済み）

### Green Tea GC

Go 1.26 の目玉機能である新ガベージコレクタ **Green Tea GC** がデフォルト有効化。GC ヘビーなプログラムで **10〜40% のオーバーヘッド削減**を実現。

- プロセッサ中心からメモリ認識型へのアプローチ転換
- 8 KiB の連続ブロック（span）単位でメモリをスキャン
- 小オブジェクト（512バイト以下）のスキャン効率を重点的に改善
- AMD64 プラットフォームではさらに約10%の追加改善が見込まれる
- Go 1.27 でオプトアウト設定が削除予定

### 自己参照型パラメータの制限撤廃

ジェネリック型が自身の型パラメータリストで自分自身を参照できるようになり、F-bounded polymorphism のようなパターンが実現可能に。

## エコシステムの動向

### Webフレームワークの現状

2026年のGoフレームワーク選定は成熟期に入り、用途に応じた明確な棲み分けが定着。

| フレームワーク | 特徴 | 適用場面 |
|---|---|---|
| **標準ライブラリ (net/http)** | Go 1.22 以降のルーティング強化で実用的に | 小〜中規模、外部依存を最小化したい場合 |
| **Gin** | GitHub Stars 75,000超、豊富なエコシステム | 汎用的なREST API開発 |
| **Echo** | 高パフォーマンス・ミニマル設計 | ミドルウェア重視の中〜大規模API |
| **Fiber** | Fasthttp ベース、Express.js ライクなAPI | 極限のパフォーマンスが求められる場合 |
| **ConnectRPC** | HTTP/1.1・HTTP/2・gRPC の統合 | マイクロサービス間通信 |

### 可観測性（Observability）の進化

2026年、Go開発者の関心は**可観測性**に大きくシフト。OpenTelemetry + eBPF によるゼロコード計装が実用段階に到達。

- **OpenTelemetry Go Auto-Instrumentation（ベータ）**: eBPF を使用した動的ランタイム計装により、コード変更やバイナリ再ビルドなしでトレース収集が可能
- **OBI（OpenTelemetry eBPF 計装）**: HTTP/S および gRPC サービスの Rate Errors Duration (RED) メトリクスを自動キャプチャ
- Go バイナリは eBPF プロファイリングとの親和性が高く、ストリップ後も完全な関数名を保持

- [Announcing the Beta Release of OpenTelemetry Go Auto-Instrumentation using eBPF](https://opentelemetry.io/blog/2025/go-auto-instrumentation-beta/)

### AI エージェント開発とGo

Go はエラーハンドリングの明確性やコンパイル・テスト実行の高速性から、AI エージェントの「コード生成 → テスト → 修正」サイクルに適した言語として注目が高まっている。

- **主要フレームワーク**: ADK、Genkit、LangChain Go、Eino、Anyi
- **設計パターン**: クリーンアーキテクチャによる AI エージェント基盤設計（Model / Memory / Tool / Agent の抽象化）が推奨される
- モデルの変更（GPT → Claude → Gemini → ローカル LLM）に耐える設計として、外部依存を Infrastructure 層に閉じ込めるアプローチが普及

## まとめ

2026年のGo言語は、**ジェネリックメソッドの導入**（Go 1.27）と **Green Tea GC の安定化**（Go 1.26）という2つの大きな言語進化を軸に発展を続けている。エコシステム面では、可観測性の標準化（OpenTelemetry + eBPF）、AI エージェント開発への進出、そしてフレームワーク選定の成熟が顕著。コミュニティ活動も世界各地のカンファレンスで活発であり、Go の需要は引き続き拡大傾向にある。
