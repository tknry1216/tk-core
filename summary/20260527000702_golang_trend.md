# Go言語トレンドサマリー（2026年5月）

## 1. 最新リリース状況

### Go 1.26（2026年2月リリース）

- **`new` 関数の拡張**: `new` のオペランドに式を指定して初期値を設定可能に
- **cgo呼び出しの高速化**: ベースラインのランタイムオーバーヘッドが約30%削減
- **ヒープアドレスのランダム化**: 64bitプラットフォームでヒープベースアドレスを起動時にランダム化し、メモリアドレス予測攻撃への耐性を強化
- **goroutineリークプロファイル**: `runtime/pprof` パッケージに goroutine リーク検出プロファイルが実験的に追加
- **`go fix` の刷新**: モダンな言語機能・ライブラリを活用したコード改善を自動提案する新実装

### Go 1.25（2025年8月リリース）

- **`testing/synctest` パッケージ正式化**: 時間の仮想化による並行コードの高速・安定テスト
- **`WaitGroup.Go` メソッド**: goroutine生成とカウントの頻出パターンを簡潔に記述可能に
- **Green Tea GC（実験的）**: GCオーバーヘッドを10〜40%削減、コンテナ環境対応の `GOMAXPROCS` 自動調整
- **Flight Recorder**: 本番環境でインシデント発生後に直近イベントを詳細スナップショットとして記録
- **DWARF v5対応**: デバッグ情報のサイズ削減とリンク時間の短縮
- **JSON v2（実験的）**: `GOEXPERIMENT=jsonv2` で有効化可能な新JSON実装

### Go 1.24（2025年2月リリース）

- **ジェネリック型エイリアスの完全サポート**: 型エイリアスにもジェネリクスのパラメータ化が可能に
- **`tool` ディレクティブ**: `go.mod` で実行可能な依存ツールを直接管理（`tools.go` ワークアラウンド不要に）
- **Swiss Tablesベースのmap実装**: CPU オーバーヘッドを平均2〜3%削減
- **GCインクリメンタルポーズ改善**: 平均15〜25%の改善
- **`go:wasmexport` ディレクティブ**: GoプログラムからWebAssemblyホストへの関数エクスポート

## 2. Webフレームワーク動向

| フレームワーク | 特徴 | 採用率・動向 |
|---|---|---|
| **net/http（標準ライブラリ）** | 依存なし・安定・Go 1.22以降のルーティング強化 | 最も広く使われているルーター |
| **Gin** | ゼロアロケーションルーティング・高パフォーマンス | 人気No.1フレームワーク |
| **Echo** | 軽量・低レイテンシ・効率的なメモリ管理 | マイクロサービスで特に人気 |
| **Chi** | `net/http` 完全互換・軽量・慣用的 | 約12%の開発者が採用、着実に成長 |
| **Fiber** | Express.jsライクなAPI・fasthttp基盤 | Node.jsからの移行層で人気 |
| **Beego** | フルスタック・REST API/エンタープライズ向け | 大規模アプリケーションで採用 |
| **Go kit** | 分散システム・マイクロサービス特化 | エンタープライズ環境で定番 |

Go Developer Survey 2025によると、Go開発者の46%がWebサイト/Webサービスの構築にGoを使用している。

## 3. AI/LLM関連エコシステム

GoがAIツーリングの言語として注目されている。Python がモデル研究・学習で主流である一方、Go は推論・デプロイ・インフラ側で強みを発揮している。

### 主要ライブラリ・フレームワーク

- **LangChainGo**: LangChainのGo実装。チェーン、エージェント、ツール、エンベディングの合成可能なコンポーネント
- **any-llm-go（Mozilla AI）**: OpenAI / Claude / Mistral / Ollama 等8プロバイダーを統一インターフェースで利用可能
- **Genkit for Go**: プロンプト管理、エンジニアリング、本番デプロイに特化
- **gollm**: 複数LLMプロバイダーへの統一API
- **Lingoose**: チャットボット、要約ツール、推薦システム構築向けフレームワーク

### ローカル/セルフホスト

- **Ollama**: Go製。ローカルでLLMを実行するオープンソースツール
- **LocalAI**: OpenAI API互換のドロップインリプレースメント（GPU不要）
- **LocalAGI**: Go製のセルフホスト型AIエージェントプラットフォーム（Discord / Slack / GitHub連携）

### MCP（Model Context Protocol）

Go向けの公式MCP SDKが提供されており、MCPサーバー/クライアントをGoで実装可能。

## 4. ジェネリクスの採用状況

Go 1.18で導入されたジェネリクスは、2026年時点でエコシステム全体に浸透しつつある。

### 採用のベストプラクティス

- **実際の重複を排除する場面で使う**: 単純な問題にジェネリクスを強制しない
- **制約（constraints）の効果的な活用**: 型安全性を確保しつつ過度に制限しない
- **段階的採用**: Go のジェネリクスはオプトイン方式。既存コードベースへの段階的統合が推奨
- **samber/lo等の関数型ユーティリティ**: Range-over-func イテレータとの組み合わせで実用性が向上

### Go 1.23以降の改善

- 型推論の改善によるボイラープレート削減
- 複合型制約による柔軟なジェネリック関数（例: `maps.Copy`）
- ゼロコストに近い型安全抽象化

## 5. マイクロサービス・クラウドネイティブ

- **構造化ロギング**: `log/slog`（Go 1.21+標準）が新規プロジェクトでのデファクトスタンダードに
- **リンター**: `golangci-lint` がCI/CDパイプラインおよびローカル開発の標準ツール
- **コンテナ対応**: Go 1.25のコンテナ対応 `GOMAXPROCS` により、Kubernetes環境でのオーバースケジューリング問題が軽減
- **IoT**: 並行接続の効率的な処理とリソース消費の最小化により、IoT領域での採用が拡大

## 6. まとめ

2026年のGoエコシステムは以下の方向に進化している：

1. **ランタイム性能の継続的改善**: Swiss Tables map、Green Tea GC、cgo高速化など、リリースごとに着実な最適化
2. **AI/LLMインフラ言語としての台頭**: 推論サーバー、MCPサーバー、AIエージェント基盤としてGoの採用が加速
3. **ジェネリクスのエコシステム浸透**: ライブラリ・フレームワーク全体でジェネリクスの活用が定着
4. **開発者体験の向上**: `go fix` 刷新、`tool` ディレクティブ、`testing/synctest` など、開発ワークフローの改善が進む
5. **クラウドネイティブ/コンテナ最適化**: コンテナ環境を意識した改善が標準に
