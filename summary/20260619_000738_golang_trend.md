## 1. Go リリース状況

| バージョン | リリース日 | 主要な目玉機能 |
|-----------|-----------|--------------|
| Go 1.23 | 2024年8月 | Range-over-func イテレータ |
| Go 1.24 | 2025年2月11日 | Generic type aliases、Swiss Tables map、FIPS 140-3 |
| Go 1.25 | 2025年8月12日 | Green Tea GC（実験的）、json/v2（実験的）、Core Types 削除 |
| Go 1.26 | 2026年2月10日 | Green Tea GC デフォルト化、errors.AsType、cgo 30%高速化 |

### Go 1.23 (2024年8月)

- **Range-over-func イテレータ**: `for-range` ループでイテレータ関数が利用可能に。Go 1.22の実験機能から正式昇格
- 新パッケージ `iter` と `slices`/`maps` パッケージのイテレータ対応関数追加
- Timer/Ticker チャネルがバッファ付きからバッファなしに変更
- `go env -changed`、`go mod tidy -diff` コマンド追加
- PGO（Profile Guided Optimization）のビルド時間オーバーヘッドを大幅削減

### Go 1.24 (2025年2月)

- **Generic type aliases**: 型エイリアスに型パラメータを持たせることが可能に
- **Swiss Tables map**: 組み込みmapの新実装、平均2-3%のCPUオーバーヘッド削減
- **`tool` ディレクティブ**: `go.mod` でツール依存関係を直接管理（`go get -tool`）
- **`runtime.AddCleanup`**: `SetFinalizer` の後継となるより柔軟なファイナライザ機構
- **`os.Root`**: ディレクトリスコープのファイルシステムアクセス
- **`testing.B.Loop`**: ベンチマーク用の新しいループパターン
- **ポスト量子暗号**: `crypto/mlkem`（ML-KEM-768/1024、旧Kyber）、`crypto/sha3`
- **FIPS 140-3準拠**: Go Cryptographic Module v1.0.0 によるネイティブFIPS対応

### Go 1.25 (2025年8月)

- **Green Tea GC（実験的）**: `GOEXPERIMENT=greenteagc` で有効化。実ワークロードでGCオーバーヘッド10-40%削減
- **`encoding/json/v2`（実験的）**: `GOEXPERIMENT=jsonv2` で有効化。デコード最大10倍高速化
- **Core Types 概念の削除**: 言語仕様の簡素化、ジェネリクスの柔軟性向上
- **コンテナ対応 GOMAXPROCS**: Linux上でcgroup CPUリミットを自動検出
- **`testing/synctest`**: 並行コードテスト用パッケージ（仮想時間でテスト可能）
- **`sync.WaitGroup.Go`**: goroutine起動パターンの簡略化
- **`net/http.CrossOriginProtection`**: Fetch metadataヘッダベースのCSRF防御
- **Flight Recorder**: ランタイムトレースの常時キャプチャ機能
- **FIPS 140-3署名4倍高速化**、`crypto/rsa` 鍵生成3倍高速化
- **DWARF 5デバッグ情報**: バイナリサイズ削減とリンク高速化

### Go 1.26 (2026年2月)

- **Green Tea GC デフォルト化**: 小オブジェクト最適化、メモリ局所性・CPUスケーラビリティ向上
- **`errors.AsType`**: ジェネリクスベースの型安全なエラー型アサーション（`errors.As` の約3倍高速）
- **自己参照ジェネリック型**: `type Adder[A Adder[A]]` のような再帰的ジェネリック型が可能に
- **cgo オーバーヘッド約30%削減**
- **スライスのスタック割り当て最適化**: コンパイラがより多くのケースでスライスをスタックに割り当て
- **実験的 `simd/archsimd` パッケージ**: SIMD操作への直接アクセス
- **ML-DSA**: ポスト量子デジタル署名アルゴリズムの実装
- **`systemcrypto`**: macOSでもデフォルト有効に（Linux/Windowsは1.25から）

## 2. ジェネリクスの進展

### タイムライン

| 時期 | マイルストーン |
|-----|-------------|
| Go 1.18 (2022年3月) | ジェネリクス導入、Core Types 概念の追加 |
| Go 1.23 (2024年8月) | Generic type aliases の実験的サポート |
| Go 1.24 (2025年2月) | Generic type aliases 正式サポート |
| Go 1.25 (2025年8月) | Core Types 概念の削除、ジェネリクスの柔軟性向上 |
| Go 1.26 (2026年2月) | 自己参照ジェネリック型、`errors.AsType` |
| 2026年3月 | **ジェネリックメソッドのプロポーザル承認** |

### 採用状況

- 2025年の新規Goプロジェクトの **73%** がジェネリクスを積極的に活用（2022年の12%から大幅増）
- Uber、Netflix、Googleなどの大企業がコアライブラリをジェネリクスパターンで書き直し

### ジェネリックメソッドの承認（2026年3月）

Go共同設計者のRobert Griesemer氏によるプロポーザルが承認。Goの長年の制限を解除する歴史的な転換点。Go 1.27以降での実装が見込まれる。

## 3. パフォーマンス改善

### Green Tea GC

- Go 1.25で実験的導入、Go 1.26でデフォルト化
- 小オブジェクトに最適化され、メモリ局所性とCPUスケーラビリティを改善
- **実ワークロードでGCオーバーヘッド10-40%削減**

### Swiss Tables Map（Go 1.24）

- 組み込みmap型の新実装
- マイクロベンチマークで **最大60%高速化**
- 全体的に平均2-3%のCPUオーバーヘッド削減

### cgo改善（Go 1.26）

- ベースラインのcgoコールコスト **約30%削減**

### コンテナ対応 GOMAXPROCS（Go 1.25）

- Kubernetes等のコンテナ環境でCPUリミットを自動検出
- オーバースケジューリングの防止

### その他

- FIPS 140-3モード署名: 非FIPSモードと同等まで高速化（4倍改善）
- `crypto/rsa` 鍵生成3倍高速化
- スライスバッキングストアのスタック割り当て最適化（Go 1.26）

## 6. WebAssembly 対応

### Go標準のWASM対応

| バージョン | 進展 |
|-----------|------|
| Go 1.11 | WASM初期サポート（js/wasm） |
| Go 1.21 | `GOOS=wasip1` ポート追加 |
| Go 1.24 | **`go:wasmexport`** ディレクティブ。WASIリアクタ/ライブラリ対応 |

### TinyGo

- 最新バージョン: **v0.41.1** (2026年4月22日)
- Go 1.26対応、最小Go 1.23
- 標準Goの8-12MBに対し、**数百KB〜50KB未満** のWASMバイナリを生成（10-20倍小さい）
- WASI Preview 1/2 両対応
- WebAssembly Component Model 対応

### Wazero

- 最新: **v1.12.0** (2025年5月)、~6.2k GitHub stars
- **純Go実装**（CGO依存なし）のWASMランタイム
- コンパイラモード（AOT）はインタプリタの **約10倍高速**
- WebAssembly 3.0仕様への準拠を推進中
- WASI Preview 2は非対応（計画なし）

### WebAssembly エコシステム全体

- **WebAssembly 3.0**: 2025年9月にW3C標準化（WasmGC、例外処理、tail calls等9機能）
- **WASI Preview 2**: 安定版。主要クラウドプロバイダがWASMベースサーバレスを提供
- **Wasmer 6.0**: ネイティブ速度の約95%を達成
- Chrome ページロードの **約5.5%** がWebAssemblyを使用（2026年初頭）

## 8. セキュリティ・サプライチェーン

### FIPS 140-3ネイティブ対応

| バージョン | 対応内容 |
|-----------|---------|
| Go 1.24 | Go Cryptographic Module v1.0.0。ネイティブFIPS対応 |
| Go 1.25 | `systemcrypto` がLinux/Windowsでデフォルト有効 |
| Go 1.26 | `systemcrypto` がmacOSでもデフォルト有効 |

BoringCrypto等のサードパーティライブラリが不要に。

### ポスト量子暗号

- **ML-KEM-768/1024** (旧Kyber): Go 1.24で実装。NIST承認のポスト量子鍵交換（FIPS 203）
- **ML-DSA**: Go 1.26で実装。ポスト量子デジタル署名

### govulncheck

- Go公式の脆弱性スキャンツール
- **到達可能性分析**: 実際に呼び出されていない脆弱な関数は報告しない（誤検知の大幅削減）
- Go脆弱性データベース（`vuln.go.dev`）: NVD、GitHub Advisory、Go メンテナ情報を集約
- VS Code統合、GitHub Actions対応、pkg.go.dev での脆弱性情報表示
- CI/CDパイプラインへの組み込みが容易

### サプライチェーンセキュリティ

- **Goモジュールチェックサム**: `go.sum` と `sum.golang.org` による透明性のある依存関係の整合性検証
- **SLSAフレームワーク**: ソースの整合性、ビルドの来歴、依存関係管理のためのセキュリティレベル
- **EUサイバーレジリエンス法** (2025年施行): SBOM公開とセキュリティ・バイ・デザインの義務化

## まとめ

2025-2026年のGoは **安定した成熟期** に入りつつも、以下の分野で大きな進化を遂げている:

1. **ランタイム性能**: Green Tea GC、Swiss Tables、cgo改善により、既存コードが「何もせずに速くなる」状況
2. **AI/MLインフラ言語としての台頭**: モデルトレーニングではなく、AIシステムの構築・デプロイ・オーケストレーションの言語として独自のポジションを確立
3. **ジェネリクスの成熟**: Core Types削除による仕様簡素化、ジェネリックメソッドの承認により、表現力が大幅に向上
4. **セキュリティファースト**: ポスト量子暗号のネイティブ対応、FIPS 140-3準拠、govulncheckの進化
5. **標準ライブラリの拡充**: json/v2、synctest、slog等により、サードパーティ依存の削減が進行

Goの **TIOBE順位は下降** したが、これは検索ベースの指標の限界を示すもの。実際の開発者数（220万人→500万人以上）、企業採用（18,000社以上）、給与水準、求人成長率はすべて上昇傾向にある。
